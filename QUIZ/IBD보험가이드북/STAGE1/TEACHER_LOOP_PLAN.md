# 선생–학생 검토·재검색 루프 설계 (2026-11-20, 초안)

> 2026-11-23: 선생 지시문을 일반 버전(해시 `60e30c0dc140`)으로 바꿨다. 아래 3절의 '유형' 목록은 맞춤 버전 기준이며, 지금 목록은 `teacher_loop.py`의 `PROBLEM_TYPES`와 `PROMPT_REVIEW.md` 4절을 따른다. 상태·실행 이름은 `self-g`·`opus-g`.

> 아직 코드·API 실행 없음. API 단계는 연구자가 '돌려'라고 할 때만, 실행 전 호출 수·비용을 보고한다. 모든 API 호출은 배치 API.

## 1. 목적

지금 RAG 에이전트(`gpt-5.6-terra` + 가이드북 PDF 상위 5쪽)의 오답을 줄인다.
오답 분석(`eval_out/오류분석_세모델_정리.md`)에서 남은 오답은 두 종류다.

| 원인 | 비중 | 예 |
|---|---|---|
| 검색: 근거 쪽이 안 들어옴 | 가장 큼. 상위 모델일수록 거의 전부 (Opus A형 잃은 9점 중 7점) | JAK 체크리스트 p.49·52, IFX IV 고시 p.36·37 대신 SC 쪽, ADA 투약간격 p.28, D형 빠뜨린 약 43 |
| 답변: 쪽은 있는데 잘못 읽음 | gpt A형 13.5점 | 조건 축약 15, 다른 기준 옮김 5, 이미 실패한 약 재사용 4 |

선생이 학생 답을 발췌와 대조해 **무엇이 부족한지, 어디서 찾아볼지 조언**하고, 코드가 그 쪽을 RAG에서 찾아 붙인 뒤 학생이 다시 답한다.

## 2. 흐름 (문항 하나)

```
0회차  학생 답  ← 기존 에이전트 답 재사용 (eval_out/<유형>_agent_gpt-5.6-terra, 비용 없음)
  ↓
선생 검토 (질문 · 발췌 · 학생 답)
  ├ 통과 ─────────────────────────────→ 확정
  ├ 다시 읽어: 지적만 돌려보냄 ───────┐
  └ 더 찾아: 찾을 곳을 요청 → 코드가 쪽 추가 ┤
                                          ↓
                         학생 재답 (발췌 + 추가 쪽 + 선생 조언)
                                          ↓
                         선생 검토 … 최대 2회 → 마지막 학생 답이 최종 답
```

- 답 형식은 지금과 같다(A·A2 `답:`, C `판정:`/`이유:`, D `인정:`/`이유:`). 채점은 바꾸지 않는다.
- 선생이 '통과'라고 한 답은 더 건드리지 않는다.

## 3. 선생

### 받는 것
질문, 문항 형식(단답 / 환자 판정 / 약 선택), 지금 발췌(`[1] p.52 · 제목` 번호 포함), 학생 답.
정답·채점 열쇠·CSV는 주지 않는다.

### 내놓는 것 (JSON, strict 스키마)

```json
{
  "판정": "통과 | 다시 읽어 | 더 찾아",
  "문제": [
    {"유형": "근거 없음 | 조건 축약 | 다른 약·적응증 기준 | 발췌에 없는 덧붙임 | 이미 실패한 약 | 빠뜨린 약 | 형식",
     "설명": "학생 답의 어느 부분이 왜 부족한지 (한두 문장)",
     "발췌 번호": [2]}
  ],
  "찾기": [
    {"약": "Upadacitinib", "질환": "UC", "쪽 종류": "체크리스트", "검색어": null}
  ]
}
```

- `쪽 종류`: `고시`(급여기준 p.35~57) · `체크리스트`(투여 전 체크리스트 p.49·52·55·57) · `투약간격`(p.28~30) · `약 설명`(p.17~27) · `재투여`(p.58~59) · `모니터링`(p.4~14) · `검색`(종류로 안 떨어질 때, `검색어` 필수).
- `찾기`는 한 번에 최대 3개.

### 지켜야 할 것 (지시문에 명시 + 코드로 검사)
- **답 내용은 말하지 않는다.** 판정(예/아니오), 기준 수치, 정답 약 목록을 쓰지 않는다. 부족한 부분과 찾을 곳만 말한다.
- 코드 검사(선생 출력마다): `설명`에 나온 숫자가 지금 발췌에 없는 숫자면 '누설 의심'으로 기록. C형 `설명`에 판정 단어(예·아니오·인정·불인정), D형에 '인정해야/넣어야 할 약' 같은 표현이 있으면 기록. 누설 의심 비율을 결과와 함께 보고한다.
- D형은 '빠진 약을 찾아봐'를 위해 약 이름을 `찾기`에 쓸 수 있다. 이것은 검색 요청이지 답이 아니지만, 선생 지식이 들어가는 통로이므로 한계로 적는다(5절 조건 ④와 ③ 비교로 크기를 본다).

## 4. 쪽 찾기 도구 (코드, 정답 안 씀)

1. `쪽 종류`가 `검색`이 아니면 **메타데이터 조회**: 가이드북 JSONL의 쪽마다 붙은 약·질환·제목으로 고른다(`simulate_retrieval.py`의 규칙과 같은 메타데이터).
   예: (Upadacitinib, UC, 체크리스트) → p.52 / (Infliximab, UC, 고시) → p.36·39.
2. 조회 결과가 없거나 `검색`이면 **기존 RAG 검색**(BM25·임베딩 → RRF → 리랭커, 백엔드 `Engine.trace`)에 `검색어`를 넣어 상위 2쪽.
3. 이미 발췌에 있는 쪽은 빼고, 요청 하나에 최대 2쪽, 한 회차에 최대 4쪽만 붙인다(발췌가 너무 길어지는 것을 막음).
4. 기록: 요청, 고른 쪽, 고른 방법(조회/검색), 붙이지 못한 이유.

`simulate_retrieval.py`로 본 상한: 지금 오답 중 검색 실패 19건은 같은 메타데이터 규칙으로 근거 쪽이 모두 들어온다. 루프가 실제로 그 쪽을 요청하는지가 이 실험의 질문이다.

## 5. 학생 재답

- 지시문: 백엔드 `generate.py`의 `_ANSWER_ONLY`/`_ANSWER_STYLE`(지금 에이전트와 같은 문장) + 한 단락:
  "선생의 검토 의견이 있습니다. 발췌를 다시 확인해 필요하면 답을 고치세요. 답의 근거는 발췌뿐이며, 선생 의견이 발췌와 다르면 발췌를 따릅니다."
- 입력: 질문, 발췌(원래 5쪽 + 추가 쪽, `_context` 형식), 이전 답, 선생의 `문제` 목록.
- 모델: `gpt-5.6-terra` (지금 에이전트와 같음).

## 7. 측정

- 유형별 정확도(A 본 점수 101, A2 38, C 198, D 37)와 네 유형 평균, ①과의 짝 비교.
- **바뀐 답:** 틀림→맞음, 맞음→틀림(고쳐서 망친 것), 회차별.
- **선생 판단의 질 (채점 후 계산):** 통과시킨 답 중 틀린 답(놓침), 고치라고 한 답 중 원래 맞던 답(헛경보).
- **쪽 복구:** 검색 실패 19건(`simulate_retrieval.py`의 NEED)과 D형 정답 약 쪽(DPAGE) 중 루프가 붙인 비율. 붙였는데도 틀린 경우는 읽기 문제로 분리.
- **안전 오답:** C형 '허용' 오답(급여 안 되는데 예), D형 이미 실패한 약·체크리스트 미달 약.
- 선생 누설 의심 비율(3절), 회차 수 분포, 문항당 토큰·비용.

## 9. 실행 방식 (배치)

회차마다 배치 하나씩. 상태는 `eval_out/teacher_loop/<조건>/state.jsonl`(문항별 회차·발췌·답·선생 출력).

```
.venv_rag/bin/python teacher_loop.py init   --arm self|opus|route [--pilot 5]   # 상태 만들기 (무료)
.venv_rag/bin/python teacher_loop.py next   --arm …   # 쪽 찾기(코드) + 다음 배치(선생 또는 학생) 요청 파일 (무료)
.venv_rag/bin/python teacher_loop.py submit --arm … --yes   # 제출 (과금)
.venv_rag/bin/python teacher_loop.py status / fetch --arm …  # 확인 · 결과 반영 (무료)
… next → submit → fetch 를 '할 일 없음'까지 반복 (선생 r1 → 학생 r1 → 선생 r2 → 학생 r2) …
.venv_rag/bin/python teacher_loop.py finalize --arm …  # eval_out/<유형>_loop-<arm>[_pilot]_gpt-5.6-terra/answers.jsonl
.venv_rag/bin/python teacher_loop.py report   --arm …  # 판정 분포 · 누설 의심 · 붙인 발췌 · 회차 · 토큰
```
- 상태: `eval_out/teacher_loop/<arm>[_pilot]/` (state.jsonl, meta.json에 지시문 해시, batches/).
- 파일럿 20문항(유형마다 5, 시드 20261120)은 `--pilot 5`로 따로 폴더를 만든다.
- 선생 출력이 깨지거나 학생 재답이 실패하면 그 문항은 직전 답으로 확정하고 report에 센다.

- 최종 답은 기존과 같은 모양이라 `score_cases.py`(C·D) · `regrade_v2_batch.py`(A·A2)로 그대로 채점한다.
- ② 라우팅만은 `expand`를 규칙 B로 한 번 돌리고 학생 배치 한 번.
- 백엔드 서버는 켤 필요 없다(쪽 조회·검색은 `.venv_rag`에서 백엔드 코드를 import, `csv_rag_retrieve.py`와 같은 방식).
